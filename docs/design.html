声と音量で flag を立てて録り、録り終えたファイルはユーザーが書いたコマンドに渡す

2026-10-29 改訂・送り先を決め打ちするのをやめて、録音ファイルを設定したコマンドに渡す形にした

アプリは録ってファイルにするところまで。その先はユーザーのコマンドが決める

  1. 送り先ごとの違い(multipart の項目名・必須の項目・先に URL を発行する手順など)を、アプリが吸収しなくて済む
  2. 認証情報はアプリが持たない。コマンドの中で Keychain(security find-generic-password)や環境変数から読む
  3. 通話中に止めるのは、通話は通話アプリ側で録ることが多く、同じ会話を二重に残さないため。オフにもできる

コマンドにはファイルのパスと時刻を渡し、終了コードで成否を受け取る

渡すもの中身例
第1引数 と TC_FILE録音ファイルの絶対パス…/recordings/2026-10-29T17-21-05.m4a
TC_STARTED_AT / TC_ENDED_ATファイルの頭と終わりの時刻(ISO 8601)2026-10-29T17:21:05+09:00
TC_DURATION_SECファイルの長さ(秒)312
TC_REASON区切った理由silence(黙った)/ max_length(60分で区切った)/ manual(メニューで区切った)/ stopped(一時停止・通話・録らない時間で止めた)/ quit(アプリを終了した)
  1. コマンドは設定に書いた1行で、/bin/zsh -lc で実行する。ログインシェルにするのは、ユーザーの PATH にある curl や whisper-cli をそのまま使えるようにするため
  2. 終了コード 0 で成功。0 以外か10分を超えたら失敗として、1分・5分あけて2回まで再実行する。3回とも失敗したらメニューバーに出し、ファイルは残す
  3. 列は1本ずつ順に流す。前のファイルの処理が終わる前に次を渡さない
  4. アプリはファイルを消さない。消したいときはコマンドの最後で消す
  5. 標準出力と標準エラーはログに残し、メニューバーから開ける

録音は「待機 → 録音中 → 終わり待ち → 引き渡し」の4状態で回る

  1. 5分待つのは、考え込む間や席を外して戻る間で1つの会話を割らないため
  2. 末尾を切らないと、毎回5分の無音をコマンドに渡すことになる。音声の長さで課金する文字起こし API では、その分が無駄になる
  3. 60分の上限は、隣で長く話され続けて flag が下がらないときの保険

音量の条件を足すと、合成音声では遠くの会話が flag から外れた

  1. 音はすべて say -v Kyoko の合成音声と桃色雑音で、遠くの会話は音量を 0.12 倍にして作った。本物の席の音量ではまだ測っていない
  2. 判定は1回あたり平均 0.075ms で、実時間の 0.23%(1スレッド)。flag が立ってから気づくまで約0.6秒で、3秒遡れば話し始めも落ちない

既定値は7つ。どれも設定で変えられ、音量のしきい値だけ仮

項目既定値決め方
flag の条件VAD ≥ 0.5 かつ ≥ -35 dBFS-35 は合成音声での仮置き。席で測って決め直す
録り始める長さ声が1秒続いたらたまたま一瞬だけ flag が立っても録らないため。0.3秒までの切れ目は同じ発話として数える
遡る長さ3秒録り始めの判定に1秒かかっても話し始めが落ちない。最初の声から数え、メモリは30秒持つので延ばせる
終わりの判定flag が5分下がり続けたら考え込む間や離席で会話を割らない長さ
渡すファイルの終わり最後の flag+5秒無音を渡さないため
1本の上限60分隣の会話が続くときの保険
終わったときのコマンド空(保存だけ)空ならファイルを保存して終わる。何もしないアプリとしても使える

配り方はサンドボックスの外にする。任意のコマンドを実行するため

  1. App Store で配るとサンドボックスが必須になり、任意のコマンドを実行できない。Developer ID で署名・公証して配る
  2. サンドボックスの中でも NSUserUnixTask なら ~/Library/Application Scripts/<bundle id>/ のスクリプトは動かせる。App Store に出したくなったら、この形に寄せる
  3. 録音には相手の同意や職場のルールが関わる(会社が職場での録音を禁止できるとした判例もある: 東京地裁立川支部 平30.3.28)。使う人が確かめる前提で、README に書く
